# 수집은 공식 API와 RSS만 쓰고, 요청 단위 재시도는 하지 않는다

스파이크에서 GitHub REST, Hacker News 공식 API(Firebase), RSS 피드는 모두 키 없이 읽을 수 있었다. 그래서 1단계 수집은 이 공식 경로만 쓰고 HTML 스크래핑은 하지 않는다. Hacker News는 Algolia 검색 API와 hnrss 같은 미러를 쓰지 않는다. Algolia는 약관을 확인하지 못했고, 미러는 공식 API와 URL이 5건 겹쳤다.

수집 실패를 숨기지 않으려고 요청 단위로는 재시도하지 않는다. 성공률을 요청 단위로 세므로(PRD 1단계 게이트), 재시도가 실패를 가리면 지표가 낙관적이 된다. 대신 잡 단위로 `2^attempts`분 뒤에 최대 3번 다시 시도한다. 요청 사이는 1초 쉬고, GitHub는 비인증 한도(시간당 60회)를 쓴다. 한도가 모자라면 `.env`의 토큰을 도입하는 것으로 이 결정을 개정한다.

## Considered Options
- Algolia HN Search API를 쓴다: 약관과 한도를 확인하지 못했다.
- 요청마다 즉시 재시도한다: 성공률이 실제 장애를 반영하지 못한다.
- 소스 사이트를 직접 스크래핑한다: 약관과 유지보수 부담이 크고 1단계 범위를 넘는다.

## Consequences
- 소스를 추가할 때마다 해당 API의 이용 약관을 확인한다(PRD 저작권과 약관).
- RSS 발행처 약관은 아직 확인하지 못했다. 피드마다 제목, URL, 짧은 발췌만 저장해서 위험을 줄였다.
