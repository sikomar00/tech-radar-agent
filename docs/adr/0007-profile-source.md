# 프로필은 생성할 때 공식 페이지 한 장을 읽어 근거로 쓰고, 그 본문은 저장하지 않는다

3단계 프로필(S3-01)의 상세 설명·특징·장단점은 제목과 280자 발췌로는 근거 있게 쓸 수 없다. 그래서 프로필을 만들 때 우리 코드가 기술당 한 장의 공식 페이지를 읽어, 본문 앞 8천 자만 모델에 데이터로 넘긴다(사용자 결정, 2026-11-08). 읽은 본문은 DB에도 파일에도 저장하지 않는다(PRD 저작권 원칙). 프로필의 각 주장은 그 페이지에 대응하는 수집 항목을 근거로 건다.

- 읽는 페이지: 연결된 GitHub 저장소가 있으면 공식 API로 README를, 없으면 그 기술의 대표 출처 URL(첫 번째 `announcement` 또는 `official` 근거, 없으면 가장 오래된 근거) 한 장을 읽는다.
- 모델에는 여전히 도구가 없고, 페이지 본문은 분류와 같은 구분자 데이터 구간에 넣고 출력은 JSON 스키마로 검증한다(ADR-0004). 본문에 근거가 없는 칸은 비워 "미확인"으로 둔다.

이 결정은 ADR-0003("HTML 스크래핑을 하지 않는다")을 프로필 생성의 한 장 읽기에 한해 개정한다. 수집은 그대로 공식 API와 RSS만 쓴다.

## 안전 규칙
- 수집 항목의 URL은 외부 글이 정한 값이라, 내부망을 찌르는 데 쓰일 수 있다. 그래서 `http`·`https`와 기본 포트만 허용하고, 호스트를 IP로 풀어 사설·루프백·링크 로컬 주소면 읽지 않는다. 리다이렉트도 같은 검사를 다시 하고 3번까지만 따른다.
- `robots.txt`가 막으면 읽지 않는다. 응답은 `text/html`·`text/plain`·`text/markdown`만, 1MB까지만 받고, 시간 제한은 20초다.
- GitHub README 읽기는 수집과 같은 비인증 한도(시간당 60회)를 나눠 쓰므로 시간당 30회까지만 한다.

## Considered Options
- GitHub README만 읽는다: ADR-0003을 바꾸지 않지만, HN·RSS에서 온 기술은 프로필이 거의 비어 "미확인"이 된다.
- 제목·발췌만 쓴다: 근거가 모자라 모델이 지어낼 위험이 크다.
- 본문을 저장해 두고 다시 쓴다: 저작권 원칙(본문 전문 저장 금지)에 어긋난다.

## Consequences
- 같은 기술의 프로필을 다시 만들면 페이지를 다시 읽는다(저장하지 않으므로). 그 사이 페이지가 바뀌면 결과도 바뀌며, 이전 주장은 `is_current`만 내리고 남는다.
- 사이트 이용 약관은 페이지마다 확인하지 못했다. 한 장만 읽고 저장하지 않는 것으로 위험을 줄였다.
