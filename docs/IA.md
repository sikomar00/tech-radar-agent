# IA v1.1 (v1.0 승인 2026-11-08, 리스팅 이유 칸 추가 2026-11-09)

기준: PRD S3-01~S3-09와 3단계 게이트, ADR-0006(서버 렌더링, 이 PC에서만), 2026-11-08 결정(Feed는 기술 단위, 화면은 단정한 문서형). 화면은 PRD대로 3개뿐이고, 기술 상세와 검색은 Knowledge Base 안에 있다.

## 사이트 구조

| ID | 화면 | 주소 | 하는 일 | PRD |
| --- | --- | --- | --- | --- |
| IA-1 | Discovery Feed | `/` | 새로 식별된 기술과 기존 기술의 업데이트를 최근 순으로 한 줄씩 본다. 줄마다 내 상태(안 읽음·저장·학습함)를 바로 바꾼다 | S3-05, S3-07 |
| IA-2 | Knowledge Base · 검색 | `/kb?q=` | 기술명·별칭·키워드로 찾고, 유형·출처·기간·내 상태로 거른다 | S3-07 |
| IA-3 | Knowledge Base · 기술 상세 | `/kb/<id>` | 프로필, 출처, 변화 이력, 내 메모를 한 화면에서 본다 | S3-01~S3-05 |
| IA-4 | System Monitor | `/monitor` | 수집·분석이 잘 도는지 보고, 분류 보류를 처리한다 | 3단계 게이트(분석 실패 원인) |

- 맨 위에 늘 같은 메뉴(Feed, Knowledge Base, Monitor)와 검색창이 있다. 검색창은 어느 화면에서나 IA-2로 간다.
- URL 수동 등록(S3-06)은 CLI(`radar add`)로 정했으므로 화면에는 없다.

## 화면별 내용

### IA-1 Discovery Feed
- 한 줄: 기술 이름, 유형(없으면 "분류 보류"), 새 기술인지 업데이트인지, **리스팅 이유**, 가장 최근 출처 제목과 날짜, 출처 수, 내 상태.
- 리스팅 이유(2026-11-09 결정): 가장 최근 출처 기준의 규칙 근거(예: "새 기술 발표 · GitHub ★543", "업데이트 · 릴리스 v1.2", "새 기술 발표 · HN 83점")와, 있으면 AI가 쓴 한 줄 이유("AI 판단: …", 미검증). 기술 상세의 출처 목록에도 출처마다 같은 칸이 있다.
- 기본은 최근 7일, 안 읽음만. 기간과 상태는 바꿀 수 있다.
- 이름을 누르면 IA-3으로 간다. 원본 글은 IA-3의 출처 목록에서 연다.

### IA-2 검색
- 결과 한 줄은 IA-1과 같은 모양이다. 별칭으로 찾아도 같은 기술이 한 줄로 나온다(3단계 게이트).
- 필터: 유형(PRODUCT, FRAMEWORK_LIBRARY, PROTOCOL_STANDARD, MODEL), 출처(GitHub·HN·RSS 발행처), 기간, 내 상태.

### IA-3 기술 상세
1. 머리: 정규명, 유형, 별칭(한·영), 성숙도, 생애주기, 내 상태와 중요도(1~5).
2. 프로필: 한 줄 설명, 상세 설명, 해결하려는 문제, 주요 특징, 기존 기술과의 차이, 활용 사례, 장점과 한계, 공식 출처. 칸마다 신뢰도와 근거 링크가 붙는다. 근거가 없는 칸은 "미확인"으로 보인다(S3-01, S3-03).
3. 출처: 연결된 수집 항목 목록(제목, 출처, 날짜, 근거 종류). 원본 링크는 새 탭으로 연다.
4. 변화 이력: 최초 공개, 릴리스 같은 이벤트를 시간순으로(S3-04).
5. 내 메모: AI가 만든 내용과 칸을 나눠, 내가 쓴 것만 보인다(S3-05).
6. 보관: 잘못 올라온 기술은 "보관" 버튼으로 치운다. 지우지 않고 `archived_at`만 채워 Feed·검색·매칭에서 빠지며, "되돌리기" 버튼이 있다.

### IA-4 System Monitor
- 수집: 소스별 최근 24시간 요청 수, 실패 수, 성공률, 마지막 실행 시각과 실패 원인.
- 분석: 오늘 모델 호출 수와 상한(375), 쉬는 중인지(연속 실패 차단), 최근 분석 실패와 원인·재시도 가능 여부(3단계 게이트).
- 잡: 대기·실행·실패 수. 실패한 잡 다시 실행.
- 분류 보류: 유형 없는 기술과 매칭 모름 항목. 줄마다 버튼으로 유형 지정, 기존 기술에 연결, 새 기술로 만들기를 한다. CLI(`radar holds`)도 그대로 둔다.

## 결정 (2026-11-08 승인 때)
1. 분류 보류는 IA-4에서 버튼으로 처리한다(CLI도 유지).
2. 잘못 올라온 기술은 IA-3의 보관 버튼으로 치우고 되돌릴 수 있다.
3. Feed의 "업데이트"는 기존 기술에 새 출처가 붙은 경우다. 같은 기술에 하루 여러 건이 붙으면 한 줄로 묶는다.
