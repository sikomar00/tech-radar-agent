# IA v1.2 (v1.0 승인 2026-11-08, 리스팅 이유 칸 추가 2026-11-09, 4단계 그래프·관계 추가 승인 2026-11-09)

기준: PRD S3-01~S3-09와 3단계 게이트, PRD S4-01~S4-08과 4단계 게이트, ADR-0002(관계 매트릭스), ADR-0006(서버 렌더링, 이 PC에서만), 2026-11-08 결정(Feed는 기술 단위, 화면은 단정한 문서형), 2026-11-09 4단계 결정(관계는 프로필 호출에서, 전체·이웃 그래프, 점선·실선, 검토 목록은 Monitor). 기술 상세와 검색은 Knowledge Base 안에 있다.

## 사이트 구조

| ID | 화면 | 주소 | 하는 일 | PRD |
| --- | --- | --- | --- | --- |
| IA-1 | Discovery Feed | `/` | 새로 식별된 기술과 기존 기술의 업데이트를 최근 순으로 한 줄씩 본다. 줄마다 내 상태(안 읽음·저장·학습함)를 바로 바꾼다 | S3-05, S3-07 |

- URL 수동 등록(S3-06)은 CLI(`radar add`)로 정했으므로 화면에는 없다.

## 화면별 내용

### IA-1 Discovery Feed
- 한 줄: 기술 이름, 유형(없으면 "분류 보류"), 새 기술인지 업데이트인지, **리스팅 이유**, 가장 최근 출처 제목과 날짜, 출처 수, 내 상태.
- 무엇인가(2026-11-09 결정): 기술이 대략 무엇인지 한 줄. 프로필의 한 줄 설명(AI 요약)이 있으면 그것, 없으면 가장 먼저 발견한 출처의 발췌(원문)를 보여 주고 어느 쪽인지 표시한다. 기술 상세 머리에도 같은 줄이 있다.
- 리스팅 이유(2026-11-09 결정): 가장 최근 출처 기준의 규칙 근거(예: "새 기술 발표 · GitHub ★543", "업데이트 · 릴리스 v1.2", "새 기술 발표 · HN 83점")와, 있으면 AI가 쓴 한 줄 이유("AI 판단: …", 미검증). 글자가 깨진 AI 판단은 숨긴다. 기술 상세의 출처 목록에도 출처마다 같은 칸이 있다.
- 기본은 최근 7일, 안 읽음만. 기간과 상태는 바꿀 수 있다.
- 이름을 누르면 IA-3으로 간다. 원본 글은 IA-3의 출처 목록에서 연다.

### IA-2 검색
- 결과 한 줄은 IA-1과 같은 모양이다. 별칭으로 찾아도 같은 기술이 한 줄로 나온다(3단계 게이트).
- 필터: 유형(PRODUCT, FRAMEWORK_LIBRARY, PROTOCOL_STANDARD, MODEL), 출처(GitHub·HN·RSS 발행처), 기간, 내 상태.

### IA-3 기술 상세
1. 머리: 정규명, 무엇인가, 유형, 별칭(한·영), 성숙도, 생애주기, 내 상태와 중요도(1~5).
2. 프로필: 한 줄 설명, 상세 설명, 해결하려는 문제, 주요 특징, 기존 기술과의 차이, 활용 사례, 장점과 한계, 공식 출처. 칸마다 신뢰도와 근거 링크가 붙는다. 근거가 없는 칸은 "미확인"으로 보인다(S3-01, S3-03).
3. **관련 기술(4단계, S4-04·S4-06):**
   - 이웃 그래프: 이 기술을 가운데 두고 1단계 이웃을 그린다. "2단계까지" 버튼으로 넓힌다. 점을 누르면 그 기술 상세로 간다.
   - 관계 목록(그래프와 같은 내용을 표로, 키보드·화면 낭독기용): 한 줄에 관계를 문장으로("Ollama는 llama.cpp 위에서 만들어졌다 · BUILT_ON"), 확인 상태(미확인·확인함), 근거 링크, "확인"·"숨기기" 버튼. 숨긴 관계는 "숨긴 관계 보기"를 눌러야 보이고 되돌릴 수 있다.
   - 직접 잇기: 다른 기술 이름(검색해서 고름)과 관계 종류를 골라 저장한다. 매트릭스(ADR-0002)를 어기면 왜 안 되는지 보여 주고 저장하지 않는다.
4. 출처: 연결된 수집 항목 목록(제목, 출처, 리스팅 이유, 날짜, 근거 종류). 원본 링크는 새 탭으로 연다.
5. 변화 이력: 최초 공개, 릴리스 같은 이벤트를 시간순으로(S3-04).
6. 내 메모: AI가 만든 내용과 칸을 나눠, 내가 쓴 것만 보인다(S3-05).
7. 보관: 잘못 올라온 기술은 "보관" 버튼으로 치운다. 지우지 않고 `archived_at`만 채워 Feed·검색·매칭·그래프에서 빠지며, "되돌리기" 버튼이 있다.

### IA-4 System Monitor
- 수집: 소스별 최근 24시간 요청 수, 실패 수, 성공률, 마지막 실행 시각과 실패 원인.
- 분석: 오늘 모델 호출 수와 상한(375), 쉬는 중인지(연속 실패 차단), 최근 분석 실패와 원인·재시도 가능 여부(3단계 게이트).
- 잡: 대기·실행·실패 수. 실패한 잡 다시 실행.
- 분류 보류: 유형 없는 기술과 매칭 모름 항목. 줄마다 버튼으로 유형 지정, 기존 기술에 연결, 새 기술로 만들기를 한다. CLI(`radar holds`)도 그대로 둔다.
- **관계 검토 목록(4단계, S4-03):** AI가 제안했지만 저장하지 않은 관계. 한 줄에 제안("A —BUILT_ON→ B"), 저장하지 않은 까닭("매트릭스 위반: PRODUCT는 PROTOCOL_STANDARD 위에서 만들어질 수 없음", "B의 유형이 없음"), 근거 링크, 버튼 두 개("유형 고치기"는 그 기술의 보류 처리로 가고, 유형이 정해지면 자동으로 다시 검사한다. "버리기"는 목록에서 내린다).

### IA-5 Knowledge Graph (4단계, S4-08)
- 점: 기술. 색은 유형, 크기는 출처 수. 점에 마우스를 올리면 이름과 "무엇인가" 한 줄, 누르면 IA-3.
- 선: 관계. 화살표는 방향(주어 → 대상, 대칭 관계는 화살표 없음), 선 위에 관계 종류. **AI가 뽑고 아직 확인하지 않은 관계는 점선, 사용자가 확인했거나 직접 이은 관계는 실선.** 숨긴 관계는 그리지 않는다.
- 기본으로 보이는 것: 관계가 하나 이상 있는 기술만. "관계 없는 기술도 보기"로 전부 볼 수 있다. 보관한 기술은 그리지 않는다.
- 거르기: 유형, 관계 종류, "확인한 관계만". 이름 찾기 칸에 적으면 그 점으로 옮겨 가 강조한다.
- 그래프 아래에 같은 내용을 표(관계 목록)로 접어 둔다(키보드·화면 낭독기용).

## 결정 (2026-11-08 승인 때)
1. 분류 보류는 IA-4에서 버튼으로 처리한다(CLI도 유지).
2. 잘못 올라온 기술은 IA-3의 보관 버튼으로 치우고 되돌릴 수 있다.
3. Feed의 "업데이트"는 기존 기술에 새 출처가 붙은 경우다. 같은 기술에 하루 여러 건이 붙으면 한 줄로 묶는다.

## 결정 (2026-11-09 v1.2 승인 때)
1. 그래프 화면은 별도 메뉴(IA-5 `/graph`)로 두고, 기술 상세 안에는 이웃 그래프와 관계 목록을 둔다.
2. 직접 이은 관계는 사용자가 근거이므로 처음부터 실선(확인함)이고, 근거 링크(수집 항목)가 없어도 된다. 그래서 4단계 게이트의 "모든 관계에 근거 1개 이상"은 **AI가 뽑은 관계**에 적용한다.
3. 그래프는 화면 낭독기로 읽을 수 없으므로, 같은 내용의 표를 늘 함께 둔다.
