# 코드 규칙 (실용 수준의 클린 코드·클린 아키텍처)
근거: *Clean Code*·*Clean Architecture*의 의존성 규칙과 SOLID. **줄 수·함수 길이 숫자는 권위 있는 단일 기준이 없어 업계 관행(린터 기본값 등)을 참고한 제안값이다.**
- 코드 쓰기 전: 구조가 걸린 작업이면 웹에서 "Clean Architecture" 자료를 확인하고 근거를 한 줄 남긴다.
- 파일: 한 가지 역할, **권장 200~300줄, 최대 500줄**(넘으면 나누고 이유를 적는다).
- 함수: 한 가지 일, **권장 30줄·경고 50줄**, 인자 3개 이하, **중첩 3단계 이하**, 순환 복잡도 10 이하.
- 의존은 안쪽(업무 규칙)으로만. DB·웹·외부 API는 경계(어댑터) 한 곳에 둔다. 계층은 필요해질 때 도입한다.
- 이름이 설명한다. 주석은 "왜"만. 중복은 세 번째에 합친다. 죽은 코드는 남기지 않는다.
- 오류는 삼키지 않는다. 입력·외부 호출 경계에서만 검증한다.
- 타입은 쓸 수 있는 언어면 명시한다(Python은 공개 함수에 타입 힌트).
- 새 라이브러리는 표준 라이브러리로 안 될 때만, 사용자 승인 후 정확한 버전으로 고정한다.
- 테스트: 동작을 바꾸면 함께 쓰고 통과 수를 숫자로 보고한다. 기존 기능이 안 깨졌음을 변경 전후 같은 점검으로 확인한다.
- UI가 필요하면 `frontend-ui-ux` 스킬(없음) 기준 대신 사용자와 디자인 취향을 인터뷰하고, 접근성(대비·키보드·대체 텍스트)을 기본으로 지킨다.
