# QA 규칙
- 기능이 끝나면 QA를 돈다. 전용 스킬은 **없음**(두 번 이상 반복되면 `skill-creator`로 만들지 묻는다).
- **Claude QA:** 수용 기준(PRD F/NF, UJ)마다 항목을 만들어 직접 실행한다. 함수 시험 → API 호출 → 내장 브라우저로 화면 클릭 순서. 결과(기대값·실제값·Pass/Fail·날짜)를 QA 시트의 "Claude" 탭과 `docs/qa-guide.md`에 등록한다.
- **사람 QA(human-in-the-loop):** 비밀번호·실계정 로그인, 메일 링크, 결제·실데이터, 실제 기기 체감, 문구·디자인 취향, 개인 데이터 화면은 대신하지 않고 "사용자" 탭 목록으로 넘긴다. 항목마다 **방법 / 정상이면 보이는 것 / 주의점**을 쉬운 말로 쓴다.
- 시트는 `google-workspace`로 템플릿을 복제해 채운다. 시트가 없으면 `docs/qa-guide.md` 표로 대신한다.
- QA 화면이 필요하면 `qa/`에 공개 키만 쓰는 점검 페이지를 만들고 설정 파일은 git에서 제외한다.
- 보고: 통과/실패를 숫자로, 실패는 숨기지 않고, 사용자 확인 목록 개수와 주의사항을 채팅 하단에 쓴다. 사용자 결과는 시트·문서에 기록하고 실패는 Intent로 올린다.
